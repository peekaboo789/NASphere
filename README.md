# NASphere

自托管的浏览器主页 / NAS 导航面板 **NASphere**：自定义图标与壁纸、含百度与 Google 的多引擎搜索框、分组卡片排序（左键长按就能拖）、容器组件（Docker 容器每张各占一块、直接摆在主页上，长按拖到任意位置、长宽随意调，实时占用与启停）、便签待办、天气小组件、账号 + 密码登录门禁，同一套页面在手机浏览器上直接可用。所有配置和图片都存在 NAS 本地，不依赖任何第三方账号或云服务。

零外部依赖：后端只用 Node.js 标准库，前端是原生 HTML/CSS/JS，无需 `npm install`、无需构建步骤。

## 功能

| 模块 | 说明 |
| --- | --- |
| 搜索 | 百度 / Google / Bing / DuckDuckGo / 搜狗预置，可增删自定义引擎（`{query}` 占位符）；引擎一律用站点官方图标（取「设置 → 小组件」里的 favicon 模板，拿不到时回退引擎名首字母），不再单独配 Emoji；输入网址回车直达；引擎选择按浏览器记住 |
| 图标 | Emoji、站点 favicon（模板可改）、图片链接、上传到 NAS、首字母兜底（favicon 失败自动回退）；图标在卡片里可选「图在上」或「图在左」，**网址应用卡片不画框，屏幕上看到的就是图标那一张图**（图标和卡片都不叠任何底色；成块的分组面板才是玻璃，见下面「外观」那行），存在服务端，所有设备一致 |
| 外观排版 | 图标大小、字体大小、卡片行距三件事各自独立：图标档位（小 / 中 / 大）决定图标框与每行能排几张（列宽贴着图标给：小 64px、中 84px、大 108px 起步），「设置 → 外观」的字体大小滑块（10–20px）只管卡片文字（**分组标题不跟它走**，固定 20px，永远比卡片字大一截），卡片行距滑块（2–40px）管行与行之间的间隔（**图标之间的横向间隔自动取行距的 0.6 倍**，撤框以后图标不再散得很开）。**图标档位选「小」时网址应用收成正方形圆角卡片**：图标在上、名称排在图标下方（最多两行；名称真要占两行时卡片只往下长一点，不把字裁掉）、「图在左」让位给这种竖排（正方形只是悬停时那层淡底的形状，平时没有底）。中、大两档完全不受这次改动影响。**Docker 容器组件不在分组网格里面，也不受图标档位管辖**，长宽和摆放坐标都各自按 px 自定，见下面「容器组件（Docker）」那一行 |
| 壁纸 | 内置 10 套渐变（默认是深色的 `midnight`，整页深色优先）、图片链接、上传到 NAS（多设备共用）、必应每日壁纸（NAS 端代理缓存 10 分钟）、无壁纸；填充方式可选裁剪铺满 / 拉伸铺满 / 完整显示；支持模糊 0–30px 与压暗 0–90%。**登录页背景直接跟随主页这张壁纸**（不再单独设置，也没有额外开关）：选「无壁纸」时登录页保持原有的深色渐变底，选必应时登录页只取 NAS 已缓存的那条地址，不会替未登录的请求去连外网。登录页中间只有一枚 **NASphere 品牌标 + 「设置 → 外观」里那个页面标题**（标在标题左边，两者并排成一行），加账号 / 密码两个输入框和一个整宽登录按钮 |
| 卡片 | **左键按住任意分组卡片约半秒就能拖起来换位**，不用先开编辑模式（容器组件也走同一套长按起拖，但它不排队换位，而是直接落在你松手的那个坐标上）：拖动中卡片实时插到指到的位置，拖到别的分组那一组就跟着收下这张卡（松手才写回配置），拖到窗口上/下边缘会自动翻页；落点按「离指针最近的那张卡 + 左半边插它前面 / 右半边插它后面」判定，跟网格排布对齐。长按之前就把指针挪开（>9px）算普通点击，松手那一下不会被当成点击而弹出标签页；**手指长按同样能拖**（触屏上按住约半秒起拖，容差放宽到 15px 才不怕手抖，起拖后页面滚动让位给拖拽，停在窗口上下边缘时按 90ms 一档自己翻页）。编辑模式（在「设置 → 数据」里勾选，或按 `E`）下额外给每张卡配 ◀ ▶ 逐步挪位置（走到分组边界会自动并入相邻分组）、⇄ 两张卡片直接互换（按一次选中，再点任意一张卡片即对调，跨分组也行，Esc 或点空白取消），并且仍支持系统拖拽；分组上下移/删除、备注（卡片上不占行，鼠标悬停时在提示里显示）；网址可分「外网网址」与「内网网址」两条分别编辑；所有链接固定新窗口打开，不会带走主页 |
| 应用管理 | 新建与编辑网址应用统一收在**「设置 → 编辑应用」**：这一栏按分组列出主页上的每一个网址应用（**容器组件不在这里，归旁边的「应用矩阵」一栏**），可以新建、逐条编辑和删除；分组头上不再有「＋链接」「＋容器」那类按钮，建组是「设置 → 数据 → 分组概览」上方的「＋ 新建分组」（见下一行）。表单里能选**所属分组**（把应用挪到别的分组＝从原分组摘掉、追加到目标分组末尾）。卡片上不再有编辑入口（右键菜单也没有「编辑」），改内容只能从这一栏的 ✎ 进 |
| 容器组件（Docker） | 容器组件不再属于任何分组，**「应用矩阵」那块窗口也撤销了**：每张组件各带自己的坐标，**直接摆在主页上**（仍然排在搜索框和分组列表之间那一层），分组网格从此只放网址应用。**每张组件有自己的宽、高和 x / y 坐标**（都是 px，宽高在下面那一栏各自的行里两个滑块调：宽 120–900、高 64–600，**只改这一张**）；**挪位置在主页上长按那张组件约半秒再拖**，摆到任意坐标、互相叠放都行，刚拖过的盖在上面（叠放次序就是配置里 `items` 的数组顺序，所以组件行不再有 ◀ ▶）。这一层的高度按最下面那张组件算，摆得再低也不会被裁掉；坐标与宽度超出屏幕时前端自己夹进可用宽，怎么摆都不出横向滚动条。**这一层没有标题头，也就没有折叠开关，更没有组件数与「运行中 x / y」这种汇总**：每个容器的状态与实时数字都在自己那张组件上，连不上 Docker 的具体原因写在「设置 → 应用矩阵」的「容器一览」那一段顶上（主页上组件的位置直接显示「Docker 不可用」）。每张组件是一块暗内凹底（状态卡要有边界才看得清，但底只用暗色、不发光），悬停时亮一档；窗口撤掉以后组件底下不再有那块玻璃面板，每张卡直接坐在壁纸上。管理这一栏的**「容器一览」把这台 NAS 上的所有容器整列摊开**，不再有下拉或选择弹层：**已经挂过组件的照样列出**，只是标一句「已在页面上」并把整行压暗，点它是去编辑那张组件而不是再加一张（所以仍然是一张组件对一个容器）；点没挂过的就往主页上加一张，落在最下面那张的下方；下面按叠放顺序列出每张组件：名称、容器名、**跟组件同一轮轮询的实时数据**（状态 · CPU · 内存 · 上/下行速率）、宽高滑块，每行右侧 ✎ 编辑（容器版表单：名称 / 图标 / 顺带的网址 / 换绑——表单里同样把这台 NAS 的所有容器整列摊开，点一个就换绑，**没有「所属分组」，因为容器已经不属于任何分组**）与 ✕ 移除（只删组件，不动 NAS 上的容器）。组件本身是「图标在左 + 名称 / 状态 · 镜像 / 实时数字」三行：名称那行最重，第二行是状态点（绿＝运行、黄＝暂停/重启、红＝停止或已不存在）+ 同样配色的状态文字 + 等宽小字的镜像名，第三行两行数字（第一行 CPU + 内存、第二行上/下行速率，标签淡色、数字白色等宽）；**备注不在这张卡上占行**（两种卡片都一样），填了也只在鼠标悬停时的提示里跟着名称出现；每 3 秒刷新一次（`docker stats` 同一套算法），停着的容器不取 stats，数字显示为「—」。**跑着的容器那枚状态点轻轻呼吸一下，停着或查不到的整张压暗一档**，一眼就能扫出哪些在服务。**启动 / 停止 / 重启整体搬进了组件的右键菜单**（卡片上不再有悬停那三个按钮，底下那条留给按钮的空当也收回来了），停止与重启会先弹一次确认；换绑只改容器名，组件上自己改过的名称与备注保持原样；没填网址的组件点开只提示一句当前状态。**只能操作已经挂在主页配置里的容器**：能查看和启停的容器集合由 `config.json` 里 `docker.items` 点名的 `container` 决定，页面上没有的容器、以及删除 / 重建 / 进容器执行命令等操作一律不开放（`rm`、`exec` 这类连接口都没有）。标签页在后台时不轮询，一张组件都没有时主页上那一层整个不出现、也完全不碰套接字 |
| 分组 | 分组头上只剩一行分组名称：**不画折叠三角**、不放分组图标、不显示条数，标题用**固定 20px 大字号**（不跟「设置 → 外观」那个卡片字号滑块走，永远比卡片文字大一截）；**点名称本身就是折叠 / 展开这一组**（折起来时名称压暗一档，表示这组还收着东西，左侧导航那枚圆点同样淡一档）。改名称、换图标（Emoji / 图片链接 / 上传到 NAS / 首字母，这枚图标只给左侧导航用）、并把这一组固定成只用内网或只用外网网址，都在「设置 → 数据 → 分组概览」每行的 ✎ 里（同一个「分组设置」弹层，主页上不再占着这个入口）；固定过的分组，导航的名称弹层会带「（固定走内网网址）」字样。**新建分组走同一个弹层，两个入口**：「设置 → 数据 → 分组概览」上方的「＋ 新建分组」（**不需要先开编辑模式**）和编辑模式下页面下方那颗。新建的组先是一张只有标题的空组，立刻出现在主页分组列表、左侧导航和「编辑应用」的所属分组下拉里，给它加应用就去「设置 → 编辑应用」 |
| 右键 | 卡片上点右键弹出菜单：打开链接、复制链接、**「⤒ 移到本组最前」「⤓ 移到本组最后」**、移除（编辑模式与非编辑模式都可用，Esc 或点别处关闭）。这两条挪的是**当前分组内部**的位置（挪完立刻写回配置，卡片已经在那一头时按钮置灰）；要换分组仍然用左键长按拖到目标分组，或去「设置 → 编辑应用」改所属分组。容器组件也有右键菜单：「打开 / 复制链接 / ▶ 启动容器 / ■ 停止容器 / ⟳ 重启容器 / ✕ 移除组件」（它不属于任何分组，也没有 ◀ ▶，挪位置就是长按那张组件拖到任意坐标）。启停按当前状态给：跑着的时候「启动」是灰的，停着的时候「停止」「重启」是灰的，数据还没回来三条一律按着。**菜单里没有「编辑」**，改内容去「设置 → 编辑应用」或「设置 → 应用矩阵」。菜单只显示操作按钮，不显示网址；打开与复制都走当前内 / 外网模式选中的那条网址；触屏设备上没有右键键，就按住卡片别动、松手出同一个菜单（一旦拖了出去就不算长按；浏览器替长按补发的那次 contextmenu 由拖拽那套管掉，不会重复弹一遍） |
| 内外网 | 屏幕右上角的图标按钮（内网＝白色房屋、外网＝白色地球）严格按模式取网址：内网只用内网网址，外网只用外网网址，不做互相回落。分组可以在「分组设置」里固定走内网或外网，**固定过的分组不受右上角全局开关影响**（只有公网地址的那一组——ChatGPT 之类——就固定外网，在家也不会被内网开关带偏）。当前模式下没填网址的卡片会变暗，点击只提示一句不跳转，所以**内外网各一条都填上**才能保证两种模式都可点。按钮状态存在浏览器本地（localStorage），家里的电脑留内网、手机在外留外网，互不干扰 |
| 外观 | **深色优先的服务门户**：页面默认就是深色（内置令牌在 JS 跑起来之前已经是深色，不会先白一下），背景 `#0a0d13`、默认强调色 `#7c8cff`、默认壁纸是深色渐变，没有大面积高饱和渐变和蓝色企业风。表面按**模块**分层，一层配方管到底：**分组面板、便签 / 待办面板、搜索框、设置弹层、右键 / 引擎菜单、输入控件、登录卡片**各是一层薄玻璃（半透明白 + 1px 发丝描边 + 顶部一道高光 + 柔和外投影 + 轻微毛玻璃），透明度递增地把「主页面板 → 弹层 → 菜单」三层拉开层次，圆角统一 20 / 14 / 10px 三档。**网址应用卡片本身仍然不画框**（无底、无边、不叠色），屏幕上看到的就是图标那一张图和它的名称，直接落在所在分组那块玻璃上——**高级感靠模块拉开，导航那一屏的效率不能被一格格的框打断**。可选性提示只有悬停：网址应用微微抬起并落一层淡底，容器组件和面板只把底色亮一档，不发光、不加粗描边。文字阴影只留给**还直接坐在壁纸上**的那几处（时钟、右上角工具区、页脚），进了玻璃面板的文字一律不加（加了就糊）；备注不占卡片上的一行，只在悬停提示里出现。浅色 / 深色两档只是玻璃更薄更透的差别，白字不变，不会出现白底块。搜索框是一条玻璃横杠（约 54px 高、**最宽 860px 居中**，引擎位与输入之间只有一道发丝分割线），框内不放任何占位提示（只显示你输入的内容），右侧按钮为白色描边放大镜（无底色）。整页内容区**最宽 1440px**（宽屏上每行能多排几个图标，超出的部分留给两侧空白，模块之间靠同一套间距刻度留出大量空白）。右上角的小工具区（白色描边房屋 / 地球 + ⚙️）平时压到 32% 不透明度，悬停或键盘聚焦才变亮，不抢视线；退出登录只放在「设置 → 安全」。登录页的 logo 位是**品牌标 +「设置 → 外观」里那个页面标题**（标题同时写进浏览器标签页），主页上不再显示大标题；品牌标是他定稿的那枚 **`NS` 双环**（青→蓝→紫渐变，左环读 N、右环读 S，两个环相扣成一个整体），白底已抠成透明，页面上只取图形那部分、下面的 NASphere 字标不进页面（标题走「设置 → 外观」，可改）。两份都在 `public/img/`：**`logo.png`**（480×323，登录页那枚，按 34px 高等比显示）和 **`favicon.png`**（64×64 方形画布、图形占宽 90%，浏览器标签页用）。渐变属于品牌色，**不跟着强调色变**。 |
| 导航 | 页面左侧一列分组图标：**图标一律染成纯白剪影，不留彩色**（Emoji、图片、首字母都走同一层 `filter: brightness(0) invert(1)`，只有悬停浮出的名称是正常文字色）；不描边、不铺玻璃块，**显现方式和右上角那组工具按钮完全一样**（整列平时压到 32% 不透明度，指针靠近或键盘聚焦进去才整体变亮），悬停单个图标向右浮出分组名，点击直接跳到该分组，滚动时当前分组靠右下角一枚强调色小点标出（图标被统一染白了，所以不再拿首字母图标的颜色当选中提示），折叠的分组再淡一档；页面右缘悬停出现滚动条，可拖动滑块或点击轨道定位，不必用鼠标滚轮；页面最末尾（所有分组之后）一行署名「© 2026 peekaboo789 · NASphere」，**跟着内容走、不再钉在窗口底部**（保存失败的提示也写在这里，同时会弹一条 toast，所以滚动到不了也不影响看） |
| 手机 | 手机浏览器直接打开就能用，**没有「移动端」开关、也没有第二套页面**，全部靠 `max-width: 720px`（窄屏版式）和 `hover: none`（触摸设备）两档媒体查询自动切。窄屏：内容区跟着屏宽收，卡片列宽只让 8px（档位本身已经贴着图标），便签与待办两栏并成一栏，设置弹层改用 `dvh` 收高并在里面滚，登录卡片占满可用宽度，左侧那列分组圆点给第一个图标让出边距。触摸设备：凡是要悬停才显现的一律常显（右上角工具区、搜索框里的引擎名），按钮放大到指头尺寸（右上角 34px、卡片上的 ◀ ▶ ✕ 20 / 24px，「小」档编辑时列宽让到 88px 才塞得下），输入框字号提到 16px（iOS 上不提这一档一聚焦就把整页放大且缩不回去），点完不残留悬停抬起的状态，长按不弹系统的链接菜单，右缘那根滚动条撤掉（手指本来就能滚），刘海与底部横杠按 `env(safe-area-inset-*)` 留白。**主页上那一层容器组件在窄屏整个不管坐标：改成从上到下的竖排**（`position` 退回常规流，每张的宽仍夹进屏幕可用宽）；配置里的 `x` / `y` / `w` / `h` 一个数字都不动，回到桌面还是你摆好的那一份。窄屏上长按组件也不会去拖位置，松手直接出右键菜单，免得手指顺手改掉桌面上排好的坐标 |

## 部署

下面是要点速览；**第一次上手、或者部署中要排查，请按 `DEPLOY.md`（部署手册）从头到尾走**，那边有逐条命令、输出含义、首启验收清单和故障排查表。

### 1. 一键脚本（推荐，含升级与回滚）

```bash
cp .env.example .env      # 改 NAV_USER / NAV_PASSWORD 为你的初始账号和密码
chmod +x deploy.sh make-image.sh
./deploy.sh               # 构建镜像 → 备份 data → 起容器 → 探活，失败自动回滚到旧镜像
```

脚本按 `docker compose`（v2）→ `docker-compose`（v1）→ 纯 `docker run` 依次挑可用的方式，参数都可用环境变量或命令行覆盖：

| 命令 | 作用 |
| --- | --- |
| `./deploy.sh --port 9000` | 换宿主机端口 |
| `./deploy.sh --data-dir /volume1/docker/nasphere/data` | 换数据目录（备份这一个目录即可迁移） |
| `./deploy.sh --dry-run` | 只打印将要执行的命令，不动任何东西 |
| `./deploy.sh --tag 1.2.0` | 指定镜像标签，默认取 `package.json` 的 `version` |
| `./deploy.sh --tar dist/nasphere-1.2.0.tar.gz` | 加载离线镜像包，跳过构建（NAS 上没网 / 拉不动 node 镜像时用） |
| `./make-image.sh` | 在有 Docker 的机器上导出 `dist/nasphere-<tag>.tar.gz` 与 `.sha256` |
| `node make-image-offline.js` | 电脑上没 Docker 也能出包：`dist/nasphere-<tag>-linux-{amd64,arm64}.tar.gz`，见 `DEPLOY.md` §5 C-2 |

行为细节：

- 升级：把项目文件覆盖成新版本（或换成新的 tar 包），再跑一次 `./deploy.sh --tag <新版本>`；配置全在 `data/`，换镜像不受影响。
- 部署前把 `data/config.json`、`data/auth.json` 复制到 `data/.deploy-backup/<时间戳>/`，只保留最近 5 份（`KEEP_BACKUPS` 可调）。回滚只换镜像，不会还原数据；要退回旧数据就把对应快照拷回去。
- 探活打的是 `/api/health`（免登录），优先用宿主机的 `curl`/`wget`，都没有时退回容器内的 node。最长等 40 秒（`HEALTH_WAIT`）。
- 探活失败会打印容器最后 20 行日志，然后自动把旧镜像重新拉起；回滚成功也仍以退出码 1 结束，方便脚本外层判断。
- 当前用户不在 `docker` 组时会自动加 `sudo`（会提示输密码）。

> 从旧名（镜像 `local/nas-nav`、容器 `nas-nav`）升上来的要注意：改名后脚本起的是新容器 `nasphere`，旧那个还占着 8080 端口，所以先 `docker rm -f nas-nav` 再跑 `./deploy.sh`。`data/` 目录一个字都不用动，配置、账号和上传的图都在里面，新容器起来就是原样。用离线包部署的，旧包（`nas-nav-*.tar.gz`）也能照常加载——`deploy.sh` 会按包里的 `RepoTags` 自动重标成 `local/nasphere:<version>`。

### 2. Docker Compose（手工）

```bash
cp .env.example .env      # 改 NAV_USER / NAV_PASSWORD 为你的初始账号和密码
docker compose up -d --build
```

浏览器打开 `http://<NAS-IP>:8080`。想让 compose 用别的端口 / 标签，`.env` 里写 `HOST_PORT=9000`、`TAG=1.2.0` 即可（含义同 `deploy.sh`）。

### 3. 纯 docker run

```bash
docker build -t nasphere:1 .
docker run -d --name nasphere --restart unless-stopped \
  -p 8080:8080 \
  -e NAV_USER='你的初始账号' \
  -e NAV_PASSWORD='你的初始密码' \
  -v /volume1/docker/nasphere/data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock \
  nasphere:1
```

最后那行套接字只为容器组件服务（不挂也能起，只是组件全显示「Docker 不可用」）；挂上它意味着这个容器能启停宿主上的任意容器，见「已知边界」。用 compose 或 `deploy.sh` 部署时这一行已经带好，`DOCKER_HOST` 也一并写好了。

### 4. 群晖 DSM（Container Manager）

1. 文件套件里建目录，例如 `/volume1/docker/nasphere`，把本项目文件放进去（SSH 里 `chmod +x deploy.sh make-image.sh`）。嫌上传整项目麻烦，可以在电脑上 `./make-image.sh`（电脑上也没 Docker 就 `node make-image-offline.js --arch <NAS 架构>`）只传 `dist/nasphere-<tag>.tar.gz` 加 `deploy.sh`、`docker-compose.yml` 三样，用 `./deploy.sh --tar` 加载。
2. 图形化：Project → 新增 → 路径选该目录 → 用内置编辑器粘贴 `docker-compose.yml` 内容（`build: .` 保留，Compose 会在 NAS 上本地构建；走离线镜像包就把 `image` 换成导入的名字、删掉 `build` 行）。命令行：直接在该目录 `sudo ./deploy.sh`。
3. 启动后访问 `http://NAS-IP:8080`。
4. 想要 `https://NAS域名/nav/` 这类入口，用「反向代理服务器」把 `nav.example.com:443` 指到 `127.0.0.1:8080`。页面里的静态资源与 API 都走根路径（`/css/...`、`/api/...`），所以反代必须整段转发到站点根（Nginx 写 `location / { proxy_pass http://127.0.0.1:8080/; }`），不要用只匹配 `/nav/` 前缀的写法。

### 5. 绿联 / 威联通

- 绿联 UGOS：Docker → Compose → 粘贴 `docker-compose.yml`，卷路径改成 `/volume1/docker/nasphere/data:/data`。
- 威联通 QNAP：容器桌面 → 创建 → 按「纯 docker run」的参数填写；网页端建议同时把 `8080` 换成未被占用的端口（QNAP 默认服务常占 `8080`）。

## 首次启动（干净版）

初始配置里**一个链接、一个分组、一个容器组件都没有**：容器第一次起来时生成的 `data/config.json` 只有默认外观、五个预置搜索引擎和天气坐标（上海）。所以首启的主页就是搜索框 + 时钟 + 天气条加底部署名，没有卡片、没有左侧分组导航、没有右缘滚动轨，主页上那一层容器组件也整层不出现（也不碰套接字）。

1. 登录后**先在「设置 → 安全」改掉默认的 `admin` / `admin123`**（没改之前页面每次打开都会提示）。
2. 「设置 → 数据 → 分组概览」点「＋ 新建分组」建第一组（不用开编辑模式）。
3. 「设置 → 编辑应用」点「＋ 新建应用」加链接：名称 + 外网网址，内网网址按家里那台机器的地址再填一条，图标可以留空走站点 favicon。**还没有分组时这一颗会提示你先去建组**，不会凭空造出一条没家的链接。
4. 要主页能看容器占用并启停：先确认这个容器挂了 `docker.sock`（compose 与 `deploy.sh` 默认已挂），再去「设置 → 应用矩阵」的「容器一览」点一个容器，一张组件对一个容器，新加的落在最下面那张的下方（摆哪儿都不合适就回主页长按它拖过去）；启停就在主页那张组件上右键。
5. 「设置 → 数据」里的**「清空为初始配置」**就是回到本节开头那个状态（写回结果与容器首启那份逐字节相同，rev 也一样），不可撤销，先点「导出配置 JSON」。

## 配置项（环境变量）

服务本身（容器内也适用）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `/data` | 数据目录，务必挂卷 |
| `NAV_USER` | `admin` | 仅当 `data/auth.json` 不存在（或老文件里还没有账号）时用于初始化登录账号 |
| `NAV_PASSWORD` | `admin123` | 仅当 `data/auth.json` 不存在时用于初始化密码 |
| `SESSION_DAYS` | `30` | 登录态有效天数（1–365） |
| `MAX_BODY` | `8388608` | 请求体上限（字节），上传图片受此约束 |
| `DOCKER_HOST` | `unix:///var/run/docker.sock` | Docker 套接字位置，容器组件靠它取实时数据与启停容器。也支持 `tcp://主机:端口`（走明文 HTTP，只在内网调试用）和 Windows 的 `npipe:////./pipe/docker_engine`。设为别的值或套接字没挂进来时，容器组件显示「Docker 不可用」，其余功能不受影响 |

`deploy.sh` / `docker compose` 这一层（写进 `.env` 或命令行传参）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `HOST_PORT` | `8080` | 宿主机端口，容器内固定监听 8080 |
| `IMAGE` / `TAG` | `local/nasphere` / `package.json` 的 version | 镜像名与标签 |
| `CONTAINER` | `nasphere` | 容器名 |
| `DATA_DIR` | `./data` | 宿主机侧的数据目录（脚本会转成绝对路径挂进容器） |
| `HEALTH_WAIT` | `40` | 探活最长等待秒数 |
| `KEEP_BACKUPS` | `5` | `data/.deploy-backup` 里保留几份配置快照 |
| `DOCKER_SOCK` | `/var/run/docker.sock` | 宿主机上的 Docker 套接字路径，会被挂进容器并写进 `DOCKER_HOST`；`deploy.sh` 找不到这个文件时只会警告并跳过挂载 |

## 直接编辑 `data/config.json`

不想开浏览器也能加链接：停不停服务都行，改完保存就是最终状态（服务端会补全并写回同一份文件）。

```jsonc
{
  "groups": [
    {
      "name": "NAS 服务",              // 也可以是字符串 "NAS 服务"
      "icon": "🗄️",                    // 分组图标：Emoji / 图片链接；不写就用分组名首字母
      "netMode": "lan",                // 可选：lan / wan 让这一组固定取内网或外网网址，不写就跟随右上角全局开关
      "links": [
        "http://192.168.1.100:5000",   // 只写网址：标题取主机名，图标走 favicon
        { "title": "群晖 DSM", "url": "192.168.1.100:5000", "icon": "🖥️" },
        { "name": "Jellyfin", "href": "192.168.1.100:8096", "emoji": "🎬", "note": "影音" },
        { "title": "NAS 管理页", "url": "https://nas.example.com", "urlLan": "http://192.168.1.100:5000" }   // 内外网各一条；两条都填才能在两种模式下点开
        // 容器不再写在这里。老配置把 container 写在分组里的，首次读取会自动摘进下面那个 docker 段，并给它补上坐标
      ]
    }
  ],
  "docker": {                         // 容器组件不再属于任何分组，也不再装进一块窗口，每张各摆各的
    "items": [
      "nginx",                        // 只写一个容器名的简写也算一条：标题取容器名，宽高与坐标都走默认
      { "title": "Jellyfin", "container": "jellyfin", "url": "http://192.168.1.100:8096", "w": 250, "h": 118, "x": 30, "y": 0 }
      // w/h 是这张组件自己的长宽 px（宽 120–900、高 64–600）；x/y 是它摆在主页那一层里的坐标 px（左上角为原点，0–4000）
      // url 可留空，只是顺带一个入口。**数组顺序就是叠放次序**：越靠后越盖在上面，主页上长按拖过的那张会被挪到最后
    ]
  },
  "notes": { "todos": ["买牛奶"] }
}
```

- 字段有别名：`title`/`name`/`label`、`url`/`href`/`link`、`urlLan`/`lanUrl`/`url_lan`、`icon`/`emoji`/`img`、`desc`/`note`；缺协议时自动补 `http://`，只写 `192.168.1.100:5000` 也可以。
- `icon` 短于 5 个字符按 Emoji 处理，看起来像路径/域名/带扩展名的按图片处理（也接受手写的 `data:image/...;base64,`）；不写 `icon` 则用 favicon，没有网址就用标题首字母。想强制某一档可以补 `iconKind`（`emoji`/`image`/`auto`/`letter`）；分组没有网址可猜，所以只有 Emoji / 图片 / 首字母三档。
- **不用手写 `id`**。首次读取时按内容生成稳定 id 并写回文件，之后拖动排序、改名、换图标才不会串位；自己写 `id`（如 `l_dsm`）会被原样保留。
- 想手改外观也可以：`appearance.theme` 取 `auto`/`light`/`dark`（默认 `dark`；`light` 只是把玻璃改薄改透，不会出现白底块），`appearance.accent` 是一个 `#rrggbb`（默认 `#7c8cff`），`appearance.iconSize` 取 `small`/`medium`/`large`（图标框与每行几张卡片；`small` 会自动把名称收到图标下方），`appearance.tileLayout` 取 `top`（图在上）/`left`（图在左），`appearance.fontSize` 是卡片文字 px（10–20，默认 `12.5`），`appearance.rowGap` 是卡片行距 px（2–40，默认 `12`），`appearance.widgets` 是 `clock`/`weather`/`notes`/`todos` 四个布尔（便签与待办默认 `false`，改成 `true` 就显示），`appearance.wallpaper.kind` 取 `gradient`/`url`/`upload`/`bing`/`none`（默认 `gradient` + `midnight`），`appearance.wallpaper.fit` 取 `cover`（裁剪铺满）/`stretch`（拉伸铺满）/`contain`（完整显示）。内置渐变的名字可以直接填进 `wallpaper.value`：`midnight`、`graphite`、`dusk`、`aurora`、`ocean`、`forest`、`sunset`、`grape`、`slate`、`paper`（认不出来的名字回落到 `midnight`）。
- `container` 填的是 **Docker 容器名**（不是 ID），字符集限定成 `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`，不合法的值会被直接丢掉（这条组件因为没有容器就不成立，会被整条丢掉）。用名字而不用 ID 是为了手改配置看得懂、容器重建之后组件也不用改。一张组件只能对一个容器，改名、挪位置、调宽高都不影响绑定。页面上管这些组件的地方是**「设置 → 应用矩阵」**：每行各自的宽高滑块、✎ 换绑（表单里整列摊开所有容器，点一个换绑，名称与备注保持原样）、✕ 移除（只删组件，NAS 上的容器不动）；**挪位置不在这一栏**，回主页长按那张组件拖到想要的位置；**加组件是这一栏上方的「容器一览」**，整列列出这台 NAS 上的所有容器；**「编辑应用」那一栏完全不显示容器**。老配置把容器卡片写在 `groups[].links[]` 里的，首次读取时会被自动摘进 `docker.items`（id 原样保留，宽高和坐标都补默认值），此后分组网格只放网址应用。
- **`x` / `y` 可以留空，也可以手填**：手填就是直接把这张组件摆在主页那一层的这个坐标上（左上角为原点，越界钳到 0–4000；摆得比屏幕还靠右也撑不出横向滚动条，前端只把**渲染**位置夹进可用宽，**配置里你写的数字一个都不改**）。早期配置根本没有这两个字段——那时候容器还集中在一块「应用矩阵」窗口里，只有窗口自己的 `docker.w` / `h` / `collapsed`：首次读取时服务会照原来的顺序从左到右、放不下就换行地给每张补一组坐标，**那三个窗口字段同时作废、写回时一并抹掉**，此后拖拽只改 `x` / `y` 和各自的 `w` / `h`。
- **Docker 组件能操作的范围就是这份配置里点名的那些容器**：`/api/docker/state` 只查 `docker.items` 里出现的名字，`/api/docker/action` 对不在里面的名字直接 403，动作只放行 `start` / `stop` / `restart`。所以手改 `config.json` 加一个容器名，等同于授权主页登录账号启停这个容器。
- 缺的字段回落默认值，超上限的会被裁掉：120 个分组、每组 300 个链接、60 张容器组件、40 个搜索引擎、300 条待办；名称 60 字、标题与备注 200 字、便签 20000 字、网址 2000 字；宽高与坐标越界按上下限钳住（单张组件宽 120–900、高 64–600，坐标 x/y 各 0–4000）。网址只放行 `http/https/magnet/ftp/file` 和 `/相对路径`，`javascript:` 之类直接丢弃。
- 打开的页面大约 20 秒内自动同步这份改动（标签页重新获得焦点时立刻同步），并弹一次「配置已更新」提示；本地还没写完的改动不会被覆盖。
- JSON 语法写错（漏逗号、用了注释）服务仍会用默认配置启动，`data/config.json` 不会被改写，日志里能看到原因；修好语法再刷新即可。

## 账号密码与备份

- 登录要账号 + 密码，两个都由你在这台 NAS 上定：默认是 `admin` / `admin123`（或用 `NAV_USER` / `NAV_PASSWORD` 首次启动时初始化）。**首次登录后请立刻在 设置 → 安全 改掉账号和密码**；仍是默认账号或默认密码时，页面每次打开都会提示。改账号名同样要填对当前密码。
- 账号比对不区分大小写、忽略首尾空格；密码只以 scrypt 哈希存在 `data/auth.json`，比对失败时不会区分「账号错」还是「密码错」（统一回「账号或密码不正确」），账号不对也照样跑一次哈希比对，免得被人拿响应快慢猜账号存不存在。
- 忘记账号或密码：停止容器 → 删除 `data/auth.json` → 用 `-e NAV_USER='账号' -e NAV_PASSWORD='新密码'` 启动，之后可再删掉这两个环境变量。
- 备份 / 迁移：整目录拷贝 `data/` 即可；或页面内「设置 → 数据 → 导出配置 JSON」（注意导出的 JSON 只含配置，上传的图片文件在 `data/uploads/`，导入到另一台机器时需要同步拷贝该目录，否则图片图标与壁纸会失效）。
- 局域网内多人共用：同一浏览器内的“记住上次搜索引擎”“默认图标类型”“内网 / 外网模式”三项偏好存在 localStorage，属于每台设备各自的选择（模式放本地是因为同一时刻家里的设备走内网、外面的设备走外网，不该互相覆盖）；登录页不记任何东西，账号密码每次都要手填，密码从来不存本地。其余内容全部在服务端，任何设备改完整页同步。

## 已知边界

- 未内置 HTTPS。公网暴露请放到反向代理（Nginx / Caddy / Traefik）后做 TLS，并强烈建议再套一层认证；本页面默认面向局域网使用。
- 天气使用 `api.open-meteo.com`，需要浏览器所在网络可访问该域名；不可用时只影响天气芯片，其余功能正常。壁纸的「必应每日」由 NAS 端代理，浏览器无需直连必应。
- Google 搜索是否可用取决于 NAS 所在网络的出口策略。
- 右键菜单的「复制链接」：浏览器只在安全上下文（HTTPS 或 `localhost`）开放剪贴板 API，用 `http://192.168.x.x:8080` 直连时会回落到旧版复制方式；两者都失败只会弹一句「复制失败，请手动选择复制」，不会静默出错。
- 单实例设计，无并发冲突处理：两个人同时编辑会互相覆盖（家庭场景一般不构成问题）。
- **容器组件需要把 `/var/run/docker.sock` 挂进本项目的容器，而能读写这个套接字就等于拥有宿主机 root**（可以起一个挂载宿主 `/` 的容器）。这是 Docker 自身的权限模型，不是本项目的开关能收窄的：主页账号请务必只给可信的人，也不要把它暴露到公网；不想给这个能力就别挂套接字（`docker-compose.yml` 里注释掉那一行即可），容器组件会统一显示「Docker 不可用」，其余功能照常。服务端仍做了两层收敛：接口能查看和启停的容器只有 `config.json` 里点名的那些，动作只放行启动 / 停止 / 重启。
- 容器组件的实时数据走 `/api/docker/state`，一次请求按 `docker.items` 里点名的容器逐个取 `stats`（每个容器 2 秒缓存、同一容器并发请求合并），页面每 3 秒轮询一次、标签页切到后台就停。挂了很多容器时会明显看到 NAS 上 `docker stats` 的开销，建议只把常看的十几个容器做成组件。

## 本地开发调试

```bash
DATA_DIR=./data PORT=18080 node server/index.js
```

改完代码跑一次语法检查：`npm run check`。容器内是 `node:22-alpine`，本地 Node ≥ 18 即可。

开发机上没有 Docker 时，容器组件可以先对着一个假守护进程验：`node _mock-docker.js`（默认听 `127.0.0.1:19999`，7 个假容器，其中一个停着、速率每秒在变），再起服务 `DOCKER_HOST=tcp://127.0.0.1:19999 node server/index.js`。这个文件只为本地自测服务，Docker 镜像里不会打包它。
