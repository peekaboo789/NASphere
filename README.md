# NASphere

**自托管 NAS 主页 / 导航面板**

自定义图标与壁纸 · 多引擎搜索 · 分组卡片拖拽 · 整页拖拽摆放 · Docker 容器组件 · 账号密码门禁 · 手机浏览器适配

**零外部依赖：后端仅使用 Node.js 标准库，前端使用原生 HTML / CSS / JavaScript。**

无需 `npm install`，无需前端构建，无需数据库。

所有配置、账号信息和上传图片均保存在 NAS 本地，不依赖第三方账号或云服务。

**作者：peekaboo789（蜂巢 @accarry）**

# 🚀 快速开始

## 方式一：一条命令安装

如果 NAS 可以访问 GitHub，推荐直接执行：

```bash
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/peekaboo789/NASphere/main/deploy.sh | bash
```

脚本会自动：

```text
检测 CPU 架构
      ↓
准备安装目录
      ↓
生成 docker-compose.yml
      ↓
拉取 GHCR 镜像
      ↓
docker compose up -d
      ↓
健康检查
      ↓
输出访问地址
```

不需要源码，也不在本机 build 镜像——镜像是公开发布在 `ghcr.io/peekaboo789/nasphere` 上的，脚本只负责 `docker pull`。

默认：

```text
安装目录：./dat
镜像：ghcr.io/peekaboo789/nasphere:1.2.2
compose 项目名：nasphere（容器叫 nasphere-nasphere-1）
宿主端口：18086
数据目录：./data（就在安装目录里）
```

`./dat` 是相对执行命令时所在的目录，想装别处就加 `--root`。

换安装目录或端口（管道执行必须带 `bash -s --` 才传得进参数）：

```bash
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/peekaboo789/NASphere/main/deploy.sh | \
  bash -s -- --root /volume1/docker/NASphere --port 9000
```

首次启动的账号密码是镜像内置的 `admin` / `admin123`，装完立刻登录去「设置 → 安全」改掉（这个容器还挂着 `docker.sock`，页面账号等于能启停宿主机上的容器）。

同一个目录再执行一次就是原地升级：`data/` 原样保留，壁纸、图标、配置、账号都不会丢；compose 文件每次由脚本重写。

安装完成后访问：

```text
http://<NAS-IP>:18086
```

例如：

```text
http://192.168.8.99:18086
```

> `ghcr.io` 上目前只发布了 `linux/amd64`。ARM 机型（群晖多数是 `arm64/v8`）这条命令会在拉镜像那一步报 `no matching manifest`，请改用下面的离线镜像方式。

## 方式二：本机已经有安装目录

`cd` 进上次装好的目录直接跑就是升级：

```bash
cd ./dat

chmod +x deploy.sh

./deploy.sh
```

脚本旁边就是本脚本生成的 `docker-compose.yml`（或者整个 NASphere 项目目录）时走就地部署，不会再下载任何东西。

部署脚本会自动：

1. 检测 CPU 架构（`x86_64` / `aarch64`，其余直接退出）
2. 检查 Docker
3. 备份 `data/config.json`
4. 备份 `data/auth.json`
5. 生成 `docker-compose.yml`
6. 从 GHCR 拉镜像
7. `docker compose up -d`
8. 检查 `/api/health`
9. 启动失败自动回滚旧镜像

# 🔄 更新 NASphere

在安装目录里执行：

```bash
./deploy.sh --tag 1.2.2
```

脚本会 pull 那个标签的镜像、用同一个 `data/` 重新起容器。不写 `--tag` 就重跑当前默认标签（`1.2.2`），ghcr 上同名标签被重推过时它会拉回新的那份。

一键安装过的那条命令也可以直接重跑。

项目数据默认保存在：

```text
./data
```

升级只换镜像，数据目录里的这些东西一个字节都不动：

```text
config.json
auth.json
uploads/
```

安装目录里那份 `.env` 也只被脚本读取、不会被改写。

因此正常升级不会影响已经设置好的主页，登录账号密码也不变。

# 🔐 首次登录

首次启动的凭据是镜像内置的默认值：

```text
用户名：admin
密码　：admin123
```

这是公开仓库上人人可查的默认密码，而且默认部署还会把 `docker.sock` 挂进容器（页面账号等于能启停宿主机上的容器）。**第一次登录后请立即进入：**

```text
设置 → 安全
```

修改账号和密码。改过一次之后 `data/auth.json` 就是唯一的凭据来源，之后重装、升级都不会把它换回去。

服务端另有两个环境变量 `NAV_USER` / `NAV_PASSWORD`，只在 `data/auth.json` 不存在时用于初始化；`deploy.sh` 不注入它们，需要时用 `docker run -e` 或 compose 的 `environment` 自己带上。

> 注意：`auth.json` 已经存在时，这两个变量不会再改动现有账号密码。

# 📦 Docker Compose

仓库里的 `docker-compose.yml` 是写死值的最小版本（镜像、端口、卷、`TZ` 都不做 `${}` 插值，也不读 `.env`）。`./deploy.sh` 不用它——脚本会在安装目录里生成一份自己的。

只用这一个文件也能装：镜像公开发布在 GitHub Container Registry，本机不需要源码、不需要 Dockerfile。

```bash
docker compose up -d
```

镜像本地没有时 compose 自己拉 `ghcr.io/peekaboo789/nasphere:1.2.2`，拉下来直接起容器。

默认访问：

```text
http://<NAS-IP>:18086
```

`docker-compose.yml` 里 `image`、端口、卷都是写死的值，不做 `.env` 插值。

改端口就直接改 `ports` 冒号左边那一位（容器内固定 `18086`，右边不要动）：

```text
- "9000:18086"
```

然后重新 up：

```bash
docker compose up -d
```

访问：

```text
http://<NAS-IP>:9000
```

升级版本时把 `image` 的标签一起改（同一个标签的内容变了就先 `docker compose pull`）。

`ghcr.io` 拉不动的机器改用离线镜像包：`docker load` 完之后补一个同名标签再起 compose——

```bash
docker load -i nasphere-1.2.2-linux-amd64.tar.gz
docker tag local/nasphere:1.2.2 ghcr.io/peekaboo789/nasphere:1.2.2
docker compose up -d
```

`ghcr.io` 上目前只发布了 linux/amd64 一份 manifest，ARM 机型（群晖多数是 arm64/v8）在线拉会报 `no matching manifest for linux/arm64/v8`——按 `uname -m` 挑 `linux-arm64` 那份离线包，上面那两行 `docker load` / `docker tag` 照做即可。多架构镜像推上来之后这条限制就没了。

这条路线和 `./deploy.sh` 二选一：两边都对外占 `18086`，后起的那个会报 `port is already allocated`（`deploy.sh` 在安装目录里生成的是它自己那份 compose）。切换前先停掉另一边——脚本起的容器现在叫 `nasphere-nasphere-1`，用 `cd ./dat && docker compose down` 收尾。

# 🐳 Docker Run

先拉镜像（想自己从源码 build 就换成 `docker build -t ghcr.io/peekaboo789/nasphere:1.2.2 .`）：

```bash
docker pull ghcr.io/peekaboo789/nasphere:1.2.2
```

然后：

```bash
docker run -d \
  --name nasphere \
  --restart unless-stopped \
  -p 18086:18086 \
  -e NAV_USER='admin' \
  -e NAV_PASSWORD='你自己的密码' \
  -v "$(pwd)/data:/app/data" \
  -v /var/run/docker.sock:/var/run/docker.sock \
  ghcr.io/peekaboo789/nasphere:1.2.2
```

`-e NAV_PASSWORD` 只在 `data/auth.json` 还不存在时生效，是唯一能在首次启动前定下非默认密码的口子——compose 和 `deploy.sh` 那两条路线都不带它。

其中：

```text
18086:18086
```

表示：

```text
NAS 宿主机 18086 → NASphere 容器 18086
```

容器内部固定监听 `18086`（镜像里 `ENV PORT=18086`），冒号右边那一位不要跟着改。

数据卷那一位同理：镜像里 `ENV DATA_DIR=/app/data`，宿主机目录挂到 `/app/data` 才会被读到。

主页要逐卷列出用量时，`deploy.sh` 会自己探这台 NAS 的存储池、给每一卷写一行只读挂载；手工 `docker run` 就自己加一行（口径见下面 📊 NAS 资源组件）：

```text
-v /volume2:/host/volume2:ro
```

卡片上「挂载点」那一段还要多给一个环境变量，容器自己看不见宿主机那一条路径：

```text
-e HOST_VOLUME_MAP='volume2=/volume2'
```

# 📦 离线部署

NAS 到 `ghcr.io` 不通（或者机型是 ARM，那边暂时只有 amd64 那份 manifest）时，在另一台机器上做出镜像包传过去：

```bash
./make-image.sh
```

生成：

```text
dist/nasphere-<版本>.tar.gz
dist/nasphere-<版本>.sha256
```

电脑上连 Docker 都没有就用 `node make-image-offline.js`，它自己去镜像仓库匿名拉基础层拼包，amd64 / arm64 各出一份。

将镜像包传到 NAS 后：

```bash
./deploy.sh --tar dist/nasphere-1.2.2-linux-amd64.tar.gz
```

脚本会：

```text
加载镜像
 ↓
按包里的 RepoTags 重新标记成 compose 要用的那个名字
 ↓
备份 data
 ↓
生成 docker-compose.yml
 ↓
docker compose up -d
 ↓
健康检查
```

`--tar` 这条完全跳过了 `docker pull`，所以 ARM 机型就用它（包挑 `linux-arm64` 那份），名字对不上脚本自动 `docker tag`。

# 🖼️ 图标

支持五种图标来源：

* Emoji
* 站点图标（按顺序自动取）
* 图片 URL
* 上传图片
* 首字母

上传支持 png / jpeg / gif / webp / avif / svg / ico，单张不超过 5MB。

自动取图标按写死的顺序一档一档试，任何一档拿到就收手，全部落空才用首字母：

```text
手动填的、或上传到 NAS 的那张
站点自己的 /favicon.ico（内网网址在前，外网网址在后）
favicon 服务模板（设置 → 小组件，默认 icon.horse）
名称首字母
```

ico 排在模板前面：站点自己那份就是原图，公共 favicon 服务多半给的是转过的 png。

这个顺序不在设置里配开关，整条链路只有 favicon 服务模板这一档能改。Emoji 与首字母两档是你明确选定的，不参与这一串。

想让图标固定下来，或者主页走 https 而内网 http 的图标被浏览器拦下：编辑应用 → 「按顺序抓取图标并存到 NAS」。服务端按同一串顺序替你出网取一次，抓回来的图存进 `/app/data/uploads/`（和上传的图同一套存法），这张卡改用固定图标，点保存才生效。没抓到时提示里会写明每一档试到什么，不装作成功。

一条应用刚进主页的那一下，服务端会替你抓这一次：新建应用保存、从「常用站点」点一格加进来，都只在这个时刻出网取图，取到了就把这张卡写成固定图标。之后这张卡每次显示都只看配置里写死的那一份，页面永远不再自动抓取——要重来只有上面那颗按钮，或者自己换一张。抓不到就一声不吭，卡片留着「设置 → 小组件 → 默认图标来源」那一档（出厂是 Emoji 🔗）；选「站点 favicon」时，留的就是浏览器按上面那串顺序自己试出来的效果。

手动选过图标的不会被这套动作盖掉：在弹层里点了 Emoji / 图片 / 首字母任一档、往图标框里打了字、点了抓取按钮、上传了图，都算你自己定的。新建时那一档只是占位，不算手动，所以抓到了就顶掉它。抓取还在路上时你改了图标，回来那份对不上就不写——手动那份说话。

出厂自带「常用」那一组的八条是配置文件里写好的，没经过「加入主页」这一步，所以不抓图；想让它们也固定成 NAS 上那一张，逐张开编辑应用点那颗按钮。

自动那一次和手动那颗按钮共用一份留档 `data/icons.json`：同一个图标地址只出网一次，第二次直接回 NAS 上那一张（响应里标 `cached`），并发抓同一个地址也只发一个请求；抓失败的地址六小时内不再重试，到点自动解禁；留档最多 400 条，超了按时间淘汰最旧的。清孤儿上传文件时这份留档算「还在用」，只被留档引用的图不会被删。

想彻底重来：设置 → 数据 → 「清空图标缓存」。留档抹掉、只靠留档保命的那几张图一起回收，主页正在用的图标一张都不动——清完只是「以后要重新抓」，六小时暂缓也跟着作废。

网址应用默认不绘制传统卡片边框：

> 图标就是视觉主体。

分组面板负责提供整体玻璃层次，避免主页被大量小卡片切割。

# 🧭 整页拖拽摆放

主页是一整张画布。开着编辑模式（按 `E`），每一块都能按住拖到任意位置：

```text
时钟
搜索框
天气
便签
待办
每个分组面板
每张 Docker 容器组件
每张 NAS 资源读数卡
```

它们共用同一套坐标、同一个叠放序，谁最后拖过谁盖在上面。不用写 JSON，也不用先填数字。

## 拖动

* 按住块上的空白处就能拖，块上缘那个小把手也能拖
* 卡片、按钮、输入框这些本来就能点的东西不拦路
* 落点先对齐网格点
* 靠近别的块的左边 / 中线 / 右边（上下同理）时自动吸上去，同时画出一条参考线
* 吸附赢过网格，吸不上的才落到格点
* 磁吸判定 6px
* 拖不出画面右缘

## 改尺寸

```text
右边那根柄    改宽
下边那根柄    改高
右下角那根柄  同时改宽和高
```

分组面板默认只有宽是自己定的，高还是由组里的卡片撑——只有拖过下边那根柄才会把高写死。

## 网格密度

设置 → 主页排列 → 网格密度：

```text
8–64px
出厂 16px
```

它只管落点对齐的步子。页面上那点格点只在编辑模式里露出来，平时看不见。

## 第一次拖动

一格坐标都没写过时，主页就是自动排版。

# 📊 NAS 资源组件

主页还可以摆 NAS 自己的读数卡，共四种：

```text

```

在：

```text

```

里点一下就往主页上加一张，摆放、叠放、宽高和容器组件完全是同一套操作。「自定义读数」能加好几张，
勾哪几行就画哪几行，新加的默认给内存 / CPU / 网络三行。

名字和图标随便改，读数本身改不了：「应用矩阵」那一栏每张读数卡右边的 ✎ 打开就是这两件事，主页上右键那张卡也是同一个弹层（这一路右键只有「编辑」与「移除组件」两格，启停那三项不出现）。图标留空
就用这张卡自带的那枚描边图形，也可以换成 Emoji 或者上传一张图片。

多行的卡（NAS 总览、自定义读数）还在同一个弹层里管一件事：每一行的小名。左边那列灰字是这一行默认的
名字，右边那一格填你想叫的，留空就用默认名。

```text
内存 / CPU / 网络 / GPU　→ 指标名
每一个卷　　　　　　　　 → 存储池名，比如 volume1
每一块物理盘　　　　　　 → 盘上写的型号，比如 WDC WD100EFAX-68
```

于是同一块盘在「影音池那块」和「仓库盘那张卡」里可以叫两个名字，型号换了、盘换了重新探出来，小名也
还认得那一行。只有一行的卡（内存卡、单个存储空间卡）没有这一列可改——那一行的名字本来就写在卡片标题上。

显示：

```text
内存：已用 / 剩余 / 总量 / 百分比
CPU：占用百分比 + 核心数 + 1 分钟负载
网络：下行 / 上行速率
GPU：占用百分比（驱动只写频率的内核——飞牛那种 Debian + i915 就在同一行写明这一格是按核心频率折算的）
存储空间：已用 / 剩余 / 总量 / 百分比 + 文件系统类型 + 宿主机挂载点（比如 `… · btrfs · /vol00/HSH721414ALN6M0`；那一行以「文件系统 / 挂载点」为主体，卡片窄放不下时省略号收口，整段连同落在的那块盘写在悬停里）
物理盘：型号 + 已用 / 剩余 / 总量 / 百分比（一块都没认出来时，写的是卡在哪一步）
```

多行的卡（NAS 总览、自定义读数）一行只放得下两个数，那里写的是「剩 2.4 TB / 3.6 TB」，百分比在最右边；
单指标那张卡有地方读整句，写「已用 1.2 TB · 剩 2.4 TB · 共 3.6 TB」。

硬盘那一行的「总量」是这块盘上文件系统加起来的容量，不是 `/sys/block` 写的那个裸容量：分区表占的、
没分出去的那些空间都不算还能写多少，文件系统满了才是真满。盘的用量不是 sysfs 直接给的——那里只有型号
和大小——是拿每卷的文件系统账按设备号归到盘上算出来的，所以卷没挂进容器就没有这一行数字，只报容量。
几块盘叠成镜像或阵列时，那份用量分不到单块盘上，整组的数字挂在每一行上（单指标卡会在这行末尾标一句）。

默认每 5 秒刷新一次，切到后台的标签页不刷。CPU 占用和网络速率都是拿累计计数作差算出来的，
所以服务起来之后的第一轮写着「刚开始采样」，第二轮才有数字。

用量条在两档变色：

```text
80%  琥珀
90%  红
```

## 只报容量，不读内容

服务端取数只有这几个来源：

```text
/proc/meminfo   → 内存两个计数
/proc/stat      → CPU 的累计 ticks
/proc/loadavg   → 1 / 5 / 15 分钟负载
/proc/net/dev   → 每块网卡的收发字节
/proc/self/mountinfo → 每个卷坐在哪个设备上、是什么文件系统（取「主:次」那一栏和类型名；挂载点那一栏只用来看这个目录坐没坐在这卷上，来源栏和子路径都不出口）
/sys/class/drm  → 显卡占用：在这张卡的子树里认 gpu_busy_percent 与各引擎的 busy_percent（i915 一份都不写，xe 的引擎叫 render0 / copy0），只写频率的那一档按 RPn→RP0 折算
/sys/block      → 盘的设备名、型号、总容量，以及每个分区 / 每个叠出设备的设备号
statfs()        → 某个目录所在文件系统的块数
```

回环、`docker0` 和一对端的 `veth` 不计入网络流量，`loop` / `ram` / `zram` / `md` 这类包出来的设备也不报成硬盘。
认盘靠的是这一份排除名单，不是猜盘名前缀：`/sys/block` 下面每一项都是符号链接，各家机器的盘名也差得远。
盘和卷对上号靠的也只有设备号那一段字符串（`/proc/self/mountinfo` 与 `/sys/block/<盘>/<分区>/dev` 写的
是同一个「主:次」，两边都由内核自己格式化）。对上之后出口的是 sysfs 里那个节点名（`sda`、`sda2`、`md0`），
不带 `/dev/` 打头——容器里的 `/dev` 根本没有宿主机的设备节点，写上前缀等于编一条不存在的路径。
挂载表里那个类型名用来做另一件事：`tmpfs` / `overlay` / `proc` / `sysfs` / `devtmpfs` / `squashfs` 这类虚拟
文件系统坐在 `/host` 下面时不当一卷列出来（它们那串数字不是任何人的存储池）。`btrfs` / `ext4` / `xfs` / `zfs`
和 `nfs` / `cifs` 这些真在用的类型一个都不滤。看不见挂载表时（容器里没有 `/proc`）一道过滤也不做，
只是那一行不写类型。
这些来源给的都是计数器，接口回来的字段是数字、名字与类型，页面不会列出一个文件名，也不会列目录里的东西。
卷那一行多出来的一段挂载点不在这几份文件里：那是宿主机路径，由生成 compose 的那一方写进 `HOST_VOLUME_MAP`
交进来（见下一节），没交就没有那一段。

## 卡片上那几句「读不到」是什么意思

```text
刚开始采样 — CPU 占用与网络速率都是作差算的，第二轮起才有数字
读不到 GPU 占用（驱动 … · 频率 …） — 这块卡的驱动不写百分比，连停车 / 峰值频率都配不齐，折不出数；只写频率的那一档不给这句，它会在同一行标「按核心频率折算（…→… MHz）」
这台机器上没有 /sys/block — 容器里看不见宿主机的 sysfs
/sys/block 里没有可用的盘 — sysfs 看得见，排除掉虚拟设备之后没剩下一块报容量的盘
查不到这块硬盘 — 配置里点名的那块盘不在这份名单里，换盘、拔盘都会这样
查不到这个卷（没挂进容器就读不到） — deploy.sh 生成的只读挂载里没有这一卷
931.5 GB（没找到挂在这块盘上的文件系统） — 盘的容量报得出，用量对不上号：系统盘、纯交换分区、或者这一卷压根没挂进来
931.5 GB（这台机器上没有 /proc/self/mountinfo） — 看不见挂载表，卷的账归不到盘上
931.5 GB（挂载表里对不上这些卷的路径） — 挂载表读得到，只是这些卷的目录不在里面（挂法特别或路径被改过）
931.5 GB（这一层里没挂进来的卷） — 一台卷都没挂进来，就没有能对上的账
已用 … · 剩 … · 共 …（整组叠出来的） — 这块盘和别人叠成镜像 / 阵列，那一行写的是整组的账，不是这一块的
```

## 卷怎么列出来

某一卷的已用 / 剩余 / 总量是对那个目录本身调一次 `statfs()` 拿到的，所以这一卷得先以只读挂载进容器的
`/host` 下面。`deploy.sh` 每次部署都探一遍这台机器：从根目录数最多两层，凡是「跟自己的父目录不在同一个
文件系统上」、并且文件系统类型不是虚拟那几类的目录都算一卷，各写一行只读挂载进它生成的 compose：

```text
/vol1:/host/vol1:ro
/vol00/HSH721414ALN6M0:/host/HSH721414ALN6M0:ro
/share/CACHEDEV1_DATA:/host/CACHEDEV1_DATA:ro
```

这套认法不认路径名字：绿联和飞牛的 `/vol1`、群晖的 `/volume1`、威联通的 `/share/CACHEDEV1_DATA`、
把池子挂在 `/mnt` 或 `/media` 底下那几种，走的都是同一句「比一下父目录的 st_dev」。父目录自己不是卷的
（飞牛那个 `/vol00` 只是坐在根文件系统上的一个空壳）会再往里数一层；已经是卷的那个就不往里翻，免得 btrfs
的子卷和容器的工作目录把清单撑长。`/proc` `/sys` `/dev` `/usr` `/var` `/snap` 这类系统树整个跳过，
条目太多的目录也不进去，一次最多 16 卷，超出写在「跳过」那一行里。同一块文件系统只报一次：数据目录正躺在
某一卷里面时，列出来的是那一卷的名字，不再另出一张「数据盘」。

`/host` 下面那一层的名字是页面认卷用的 id，不是宿主机路径照抄：叶子名撞车时带上上一层（`/disk1/pool` 和
`/disk2/pool` → `pool` 与 `disk2-pool`），中文卷名这种整个不在字符集里的落回上一层那个名，两层都不在就按
顺序给一个（`vol3`）。卡片上显示的名字随时能在 ✎ 里改，改的只有显示名。

登录后 `GET /api/system/state` 里的 `volumes` 就是这个形状（`total` / `used` / `avail` 是字节数，`pct`
已经四舍五入到一位小数，`fs` 是挂载表里那一行写的文件系统类型，`mount` 是这一卷在宿主机上的挂载点，
`device` / `partition` 是它落在的 sysfs 节点名）：

```text
"volumes": [
  {
    "id": "HSH721414ALN6M0",
    "name": "HSH721414ALN6M0",
    "fs": "btrfs",
    "mount": "/vol00/HSH721414ALN6M0",
    "device": "nvme0n1",
    "partition": "nvme0n1p1",
    "total": 13000000000000,
    "used": 6000000000000,
    "avail": 7000000000000,
    "pct": 46.2
  }
]
```

卡片那一行以「文件系统 / 挂载点」为主体：`name` 加那三个数，末尾再带上 `fs` 和 `mount`；`device` /
`partition` 只写在悬停里，窄卡上放不下。认不出来的那几段一律给空串，页面跟着省掉那一段——整张卡不会因为
少一段信息就写个「未知」占位。`mount` 空不空取决于下面这一份对应关系有没有交进来。

容器里的挂载表只有 `/host/<挂点名>` 这一层，宿主机那一条路径它在容器里怎么也看不见，所以 `deploy.sh`
在生成挂载的同时把「挂点名 = 宿主机绝对路径」一份份写进 `environment`：

```text
HOST_VOLUME_MAP: 'vol1=/vol1;HSH721414ALN6M0=/vol00/HSH721414ALN6M0;data=/vol2/1000/dockers/NASphere/data'
```

几卷之间用分号，每一项在第一个 `=` 处切开（挂点名不能带 `=`，所以切得不歧义）。认不出的项——挂点名不合
字符集、路径不是绝对路径、带控制字符、长过 200 字符——整条丢掉，不留半截。手写 compose 的人要让卡片也
显示挂载点，就得自己补这一行，格式同上；不写也能用，只是那一段空着。一次最多认 64 项。

不想让它自动探，就在 `.env` 里点名单：

```text
HOST_VOLUMES=/volume1 /volume2
```

只要数据目录那一卷、别的都别挂进来：

```text
HOST_VOLUMES=none
```

NAS 上新增或删除卷之后要重跑一次 `./deploy.sh`，「NAS 资源」那一列才会跟着多一行或少一行。
手工 compose 路线自己加那一行 `:ro` 挂载、再把对应的 `HOST_VOLUME_MAP` 一起补上就行。

卡片上点名的那一卷要是没挂进来，卡片会整张压暗并写着「查不到这个卷」，配置不用动。

⚠️ 注意边界：一卷一旦挂进容器，容器进程技术上就能读它的文件内容，哪怕页面只显示数字。
逐卷用量换的是这个代价，不接受就写 `HOST_VOLUMES=none`。另一层是页面这一侧：`mount` 那一串是宿主机的
真实路径，跟着 `/api/system/state` 一起回来，而这个接口要登录——所以看得见它的只有登录过的人，未登录
只有登录页。

## 为什么不靠 docker.sock 拿宿主机容量

容器里挂了 `/var/run/docker.sock`，也照样拿不到宿主机文件系统的账：

```text
docker system df   → 镜像 / 容器 / 卷各自占了多少，不是宿主机还剩多少
docker info        → 存储驱动那几行数字是容器自己那层 overlay 的账
```

Engine API 也没有「把宿主机的 `df` / `findmnt` / `lsblk` / `/proc/mounts` 给我」这类调用：那些是宿主机
进程才能读的东西，socket 后面那个 daemon 不会替客户端执行命令。所以这条路不是没试，是它给不出这些数据，
这里就不假装给得出。

所以主页的卷读数一点没用上 socket，靠的是 `deploy.sh` 生成的那几行只读挂载：

```text
/volume1:/host/volume1:ro
```

在挂载点上调 `statfs()` 拿到的是宿主机那个超级块的数字，不是容器视角的 `df`。项目里没有 `df`、没有
`child_process`，取数的来源全在「只报容量，不读内容」那一节列着。

于是两件事各自独立：

```text
Docker 组件 → 要 socket，只到容器状态与启停为止
逐卷用量   → 要 /host 那一行只读挂载，跟 socket 一点关系都没有
```

只挂 socket、没挂卷，主页就会写着「查不到这个卷（没挂进容器就读不到）」；这一句和「只挂 socket 能
读到宿主机容量」是同一件事的两面。想让读数跑起来又多给一层权限，代价就是上面那条边界。

# ⚠️ Docker Socket 安全说明

如果挂载：

```text
/var/run/docker.sock
```

NASphere 容器实际上拥有很高的 Docker 控制权限。

Docker Socket 本身可以间接获得宿主机级别控制能力。

因此：

* 不建议直接暴露 NASphere 到公网
* 建议只允许可信用户登录
* 公网访问建议再增加反向代理认证
* 如果不需要 Docker 容器组件，可以不挂载 Docker Socket

不挂载 Socket：

```text
NASphere 主页
      ↓
正常使用
```

只是：

```text
Docker 组件
      ↓
Docker 不可用
```

不会影响搜索、图标、壁纸、分组等其他功能。

分组还可以固定：

```json
"netMode": "lan"
```

或者：

```json
"netMode": "wan"
```

固定后的分组不会受到全局开关影响。

取址规则：

```text
两条都填　→ 内网用内网网址，外网用外网网址
只填一条　→ 两种模式都用这一条
两条都没填 → 卡片变灰，点了不跳转
```

所以内网工具只填内网地址、外部站点只填外网地址就够了，切换模式不会把卡片切到点不动的状态。

# 📝 直接编辑配置

可以直接编辑：

```text
data/config.json
```

例如：

```json
{
  "groups": [
    {
      "name": "NAS 服务",
      "icon": "🗄️",
      "links": [
        {
          "title": "Jellyfin",
          "url": "https://media.example.com",
          "urlLan": "http://192.168.8.99:8096",
          "icon": "🎬"
        }
      ]
    }
  ]
}
```

支持字段别名：

```text
title / name / label
url / href / link
urlLan / lanUrl / url_lan
icon / emoji / img
desc / note
```

缺少协议时自动补：

```text
http://
```

主页上的组件都写在 `docker.items` 里，数组顺序就是叠放顺序，两种卡片混在同一个数组：

```json
{
  "docker": {
    "items": [
      {
        "title": "qBittorrent",
        "container": "qbittorrent",
        "w": 250,
        "h": 118,
        "x": 10,
        "y": 10
      },
      {
        "title": "内存",
        "icon": "🧮",
        "iconKind": "emoji",
        "res": "mem",
        "w": 250,
        "h": 118,
        "x": 330,
        "y": 10
      },
      {
        "title": "volume2",
        "res": "vol",
        "vol": "volume2",
        "w": 250,
        "h": 118,
        "x": 650,
        "y": 10
      },
      {
        "title": "NAS 总览",
        "res": "overview",
        "w": 320,
        "h": 240,
        "x": 10,
        "y": 200
      },
      {
        "title": "自定义读数",
        "res": "custom",
        "rows": [
          "mem",
          "cpu",
          "net",
          "vol:volume2"
        ],
        "rowNames": {
          "vol:volume2": "影音池",
          "disk:sda": "仓库盘"
        },
        "w": 300,
        "h": 156,
        "x": 350,
        "y": 200
      }
    ]
  }
}
```

带 `container` 的是容器组件，带 `res` 的是读数卡（`mem` / `vol` / `overview` / `custom`），两者都没有的就是废条目，读取时直接丢掉。`vol` 写的是 `/host` 下的目录名，也就是「NAS 资源」那一栏里列出来的名字。

`custom` 那张的 `rows` 就是勾了哪几行，按勾的顺序从上往下画：

```text
mem      cpu      net      gpu      vols      disks
vol:<卷名>        disk:<盘名>
```

`vols` / `disks` 是「每个卷一行」「每块盘一行」，跟点名的 `vol:` / `disk:` 同时勾会把那一卷画两遍，所以设置里的勾选框会把冲突的那格先按住。认不得的键、重复的键都会在保存时丢掉；一行都没勾，卡上就写着「还没勾选要显示哪一行」。

`rowNames` 是上面那一列小名，键还是 `rows` 那套键（`vols` / `disks` 展开后要写具体的 `vol:<卷名>` / `disk:<盘名>`），值是最多 60 个字的显示名。勾了 `vols` 没点名某一卷时，给那一卷起的小名照样生效。画不到的键留着也不碍事，值写空等于不改名。

主页上各块的摆法写在 `layout` 里，一个坐标都没给就是自动排版：

```json
{
  "layout": {
    "grid": 16,
    "modules": {
      "clock": { "x": 20, "y": 30, "w": 300, "h": 90, "z": 10 },
      "search": { "x": 20, "y": 150, "w": 860 },
      "weather": { "x": 900, "y": 30, "w": 120, "h": 32, "z": 12 },
      "notes": { "x": 20, "y": 230, "w": 320, "h": 200 },
      "group:分组id": { "x": 20, "y": 460, "w": 660, "z": 15 }
    }
  }
}
```

键只有这几种：

```text
clock      search     weather
notes      todos      group:<分组 id>
```

容器组件与读数卡不住这一栏——它们本来就各带 `x` / `y` / `w` / `h`，住在 `docker.items` 里，跟这些块共用同一张画布、同一个叠放序。

四个数各存各的：只给宽就只写宽，高没给就还是自动高（内容撑多高就多高）。`x` / `y` 没给按 0 算，`z` 没给就按数组先后画。

分组删了、部件关了，它那一格坐标跟着清掉；认不出的键一律不落地。

# 🛠️ 环境变量

## NASphere 服务

| 变量             | 默认值                           | 说明            |
| -------------- | ----------------------------- | ------------- |
| `PORT`         | `18086`                       | 容器内服务监听端口（对外端口用 `HOST_PORT`，默认 18086） |
| `HOST`         | `0.0.0.0`                     | 监听地址          |
| `DATA_DIR`     | `/app/data`                   | 数据目录（镜像里 `ENV DATA_DIR`，宿主机的 `./data` 要挂到这个点） |
| `NAV_USER`     | `admin`                       | 首次初始化账号       |
| `NAV_PASSWORD` | `admin123`                    | 首次初始化密码（`deploy.sh` 和仓库那份 compose 都不注入它，只有 `docker run -e` 那条路线能带） |
| `SESSION_DAYS` | `30`                          | 登录有效期         |
| `MAX_BODY`     | `8388608`                     | 请求体上限         |
| `DOCKER_HOST`  | `unix:///var/run/docker.sock` | Docker API 地址 |
| `HOST_VOLUME_MAP` | 空                         | 卷在宿主机上的挂载点，格式 `<挂点名>=<绝对路径>`、分号隔开。`deploy.sh` 生成的 compose 自动带这一行；手写 compose 不填也能跑，只是卡片上少「挂载点」那一段。详见「卷怎么列出来」 |
| `NAV_SYS_ROOT` | `/`                         | 自测用：把 `/proc`、`/sys`、`/host` 的读取前缀指到别处，正常部署不用配 |

## deploy.sh

下面这些只有 `deploy.sh` 读（手工 `docker compose up -d` 不读，仓库那份 `docker-compose.yml` 里是写死的值）：

| 变量              | 默认值                        | 说明            |
| --------------- | -------------------------- | ------------- |
| `INSTALL_ROOT`  | `./dat`                    | 安装目录（相对当前目录），等价于 `--root` |
| `IMAGE`         | `ghcr.io/peekaboo789/nasphere` | 镜像仓库，换 fork 或内网仓库就改它 |
| `TAG`           | `1.2.2`                    | 镜像标签（脚本里写死的默认值，不读 package.json） |
| `HOST_PORT`     | `18086`                    | NAS 宿主机端口     |
| `DATA_DIR`      | `<安装目录>/data`              | 宿主侧数据目录      |
| `TZ`            | `Asia/Shanghai`            | 写进 compose 的容器时区 |
| `HOST_VOLUMES`  | 空（自动探）                 | 留空时 `deploy.sh` 探这台 NAS 的存储池（根下一层，再往下一层），每一卷各挂成 `/host/<名字>:ro`；写空格分隔的目录就是点名单，`none` 是只挂数据目录、别探 |
| `COMPOSE_PROJECT` | `nasphere`                | compose 项目名，容器叫 `<项目名>-nasphere-1` |
| `HEALTH_WAIT`   | `40`                       | 健康检查等待秒数      |
| `KEEP_BACKUPS`  | `5`                        | `data/.deploy-backup/` 保留几份 |
| `DOCKER_SOCK`   | `/var/run/docker.sock`     | 挂进容器的 Docker Socket，找不到就不挂 |

`.env` 只在安装目录里那份生效（`<安装目录>/.env`，不是执行命令时的当前目录），生效顺序：

```text
命令行 > 环境变量 > .env > 默认值
```

`deploy.sh` 不再碰账号密码：`NAV_USER` / `NAV_PASSWORD` / `SESSION_DAYS` / `MAX_BODY` 都不由它注入，要改就走服务端的环境变量（`docker run -e` 或自己编辑生成出来的 compose）或页面里的「设置 → 安全」。

图标改成「进主页的那一下」抓一次并固定：新建应用保存、从「常用站点」点进来，服务端只在这个时刻按写死的顺序出网取一次图（站点自己的 `favicon.ico` 排在第三方模板前面），存进 `data/uploads/` 并把这张卡写成固定图标。之后这张卡每次显示都只看配置里那一份——刷新、切内外网、右键编辑、换尺寸档都不再出网；要重来只有编辑应用里那颗按钮，或者自己换一张。抓不到就一声不吭，卡片维持原来能显示的效果，不弹红条。手动选过图标的（Emoji、图片、上传任一档）不会被这套动作盖掉。

修一处：新建应用出厂默认那一档是 Emoji（🔗），而原先那道门槛只放「站点图标」档过去，于是每一条新建的卡都被挡在外面，自动抓图实际上一次都没发生过。现在改成认「你有没有真动过图标」：默认那一档只是占位，抓到就顶掉、抓不到就留着；抓取还在路上时你自己改了图标，回来那份不写。

自动那一次和手动那颗按钮共用一份留档 `data/icons.json`：

```text
抓到 → 记文件名和时间，同一个网址再问直接回 NAS 上那一张（响应标 cached），零出网；并发抓同一个地址也只发一个请求
没抓到 → 记错误，六小时内不再重试，到点自动解禁
```

留档最多 400 条，超了按时间淘汰最旧的；清孤儿上传文件时它算「还在用」。设置 → 数据 里有「清空图标缓存」：只抹留档和只靠留档保命的那几张图，主页正在用的图标和壁纸一张不少，六小时暂缓一起作废；清完再加进来的还是同一个文件名，因为图按内容命名。出厂那八条没经过「加入主页」这一步，所以不抓图。

## v1.1.0

这一版不加功能，全是排查出来的缺陷：一键安装脚本有三处「该报错不报错、该回滚不回滚」，服务端有一条不带任何身份的路径请求就能让整个服务退出、另有几处坏值被静默吞掉，页面有几处会在特定操作顺序下抛异常或画错，网络读数还会把同一份流量数两遍。

**`deploy.sh`：起容器失败时真的能走到回滚**

以前在 `set -e` 底下，`docker compose up -d` 一挂就当场结束，后面「等健康检查 → 自动回滚到旧版本」整段跑不到——而旧镜像明明还被脚本留着（`$IMAGE:rollback`）。现在这一步的失败折成一个标记，不等健康检查直接进回滚，末尾仍以部署失败、退出码 1 收场，外层脚本照样能判。

**`deploy.sh`：探到的卷刚好叫 `/data` 时不再撞名**

挂点名那套避让只躲开已经用过的名字，而末尾那条 `data=<数据目录>` 是写死的、没参与避让。于是同一份 compose 里可能出现两个 `data=`，谁生效只看解析顺序。现在这个名字先被占住，卷会被让到别的挂点名，宿主机路径照样映射得进来。

**`deploy.sh`：超长数字参数会被拦下**

`[ "23 位的数" -gt 65535 ]` 不是「假」，是当场报错并返回状态 2；报错落在 `if` 的条件里就等于没拦住，脚本会带着这个假端口往下走，健康检查那道 `while` 也会因为同样的报错一次都不进。端口、`HEALTH_WAIT`、`KEEP_BACKUPS` 现在比大小之前先按位数掐一道，报错文案不变。

**页面：操作顺序撞上的几处异常**

- 容器组件的轮询定时器收成一个出口，改名、重渲染、来回切换不会再留下没人管的旧定时器——以前撤光组件之后，后台还在每 3 秒问一次接口。
- 资源读数卡的高度改成按「真正画出来的行数」算。勾上「存储空间」「硬盘」这类会展开成多行的读数时，以前按勾选项数算高度，卡片不够高，上下两头各被裁掉一截。
- 长按拖动容器组件的中途，如果配置被别处刷新（另一台设备保存、重新登录），指针底下那张卡会被换掉。以前这里抛 `Cannot read properties of null`，拖动当场断掉；现在安静收尾。落点那一步也补了同样的判断：卡片已经不在文档里时量出来全是 0，写回去会让它跳到左上角，现在直接不写。
- 网址卡拖到一半同样重画过时，插入位没得算，现在只当白拖一次，松手那一下的 click 照样吃掉，不会误打开应用。

**服务端：一条不带身份的路径请求就能让整个服务退出**

`GET /%00` 这种带 NUL 字节的路径，最后落到 `fs.statSync` 上会在同步路径里当场抛 `TypeError [ERR_INVALID_ARG_VALUE]`；`Cookie: sid=%zz` 这种畸形百分号编码会在 `decodeURIComponent` 抛 `URIError`。两者都不在任何 try 里，于是随便一个匿名请求就能把整个 Node 进程带走，服务从此无人应答。现在这两处调用点都收进一层「解不出来就当空串」的封装，路径认不出来按不存在处理、畸形 Cookie 按未登录处理。

拿修之前那一版做了对照：同一份裸字节请求（绕开 curl 和 Node 自己的 URL 规范化，直接用 socket 写）打过去，旧版进程退出码 1、端口从此没人应答；新版答 404，进程还活着。`%zz` 是同类的另一处调用点，只在新版上验过行为（答 200、进程在），旧版那条没单独复现——因为对照跑到第一条就已经死了。

**服务端：坏值不再静默**

- Docker 应答写了一半就断链（`dockerd` 被重启、被 OOM 掉）时，以前只等 `res` 的 `'end'`，而那个事件永远不来，超时也救不了——套接字已经没了，空闲计时器不再响。实测这样两条请求全挂死，缓存层里那份 pending 也永远清不掉，容器面板从此再也刷不动。现在 `error` / `aborted` / `close` 三个信号都接上，配一道「只落地一次」的闸收尾。
- `dockerList()` 失败给的是 `null`，空列表才是真的一个容器都没有。以前两者混成「可用、0 个」，面板上一片空白加一句假的可用；现在接口明说「Docker 没能给出容器列表」。
- `config.json`、凭据和内部密钥改走「同目录临时文件 + 原子改名」，权限 0600。以前写一半被断电、被 OOM 掉，留下的就是半个 JSON；而 `auth.json` 一坏，读它的分支直接退回默认口令——主人改过的密码凭空失效，门反倒对默认口令开着。
- 改密码先落盘、再换内存里那一份：盘满或只读挂载写坏了就维持旧密码，不会出现「这一轮会话用新密码、重启又回旧密码」。
- 网址解析补上 `localhost:3000` 这种只写「主机名:端口」的常见写法，和 `//host/x` 这种协议相对写法；`javascript:` / `data:` / `chrome:` 冒号后面不是数字，走不到补 `http://` 那一条，其余看不懂的协议一律丢掉。
- `fs.stat` 点过头之后文件还能消失（改配置触发的清理正和这一枪抢同一个文件），那时读流抛 `'error'`，没人接就是又一个未捕获异常。静态文件和上传的媒体现在走同一个出口：接住错误、断掉这条连接，而不是让整个服务陪着。

**网络读数：同一份流量不再数两遍，也说明白数的是哪一层**

- 一块网卡被 bond 或 bridge 收编之后（`/sys/class/net/<name>/master` 存在），上层那一个已经把它的收发量数进去了，旧逻辑把两边一起加，主页那一格就明显翻倍。现在从属网卡跳过，只认带 `device`（真网卡）或带 `lower_*`（bond / bridge 这一层）的那些。
- 容器里看不见宿主机的网卡，只看得见自己那一层的虚拟网卡。这种情况读数带一个 `localOnly`，主页那一格会写明「只数得到容器自己的流量」，不拿它冒充整台 NAS 的流量；`/sys/class/net` 读不到时不猜，这个字段干脆不给。网卡名、`/sys/class/net`、`/dev/` 这些一律不出接口。

## v1.0.8

改的是两件「看得见但说不清」的事：卷用量到底来自宿主机哪一个挂载点，核显那一格到底是实测还是估的。

存储空间那一行现在带完整路径：

```text
以前　　→ 已用 6.0 TB · 剩 7.0 TB · 共 13 TB · btrfs
现在　　→ 已用 6.0 TB · 剩 7.0 TB · 共 13 TB · btrfs · /vol1
```

卷多出三个字段，主页那一行、悬停提示和 `/api/system/state` 三处都能看见：

```text
挂载点　→ 这一卷在宿主机上的绝对路径，用量就是从它问出来的
设备     → sda / nvme0n1 / md0 / dm-1，只给名字不给 /dev/ 前缀
分区     → sda2 / nvme0n1p1，同一块盘上的几个池子靠这个分开
```

路径不是容器自己猜的。`deploy.sh` 探到一卷之后，把「挂点名 = 宿主机绝对路径」这一对写进它生成的
compose，容器里读这个名字，拿到的是宿主机那一份超级块的账：

```text
HOST_VOLUME_MAP=vol1=/vol1;vol2=/vol2
```

老 compose、手写 compose 没交这一行的，挂载点就空着，字段仍在接口里——绝不拿 `/host/vol1` 这种
容器内部的摆位冒充宿主路径。硬盘那一行的用量还是从卷归过去的：拿挂载点的设备号去对
`/sys/block/<盘>/<分区>/dev`，认得到的盘才有数字，认不到只报裸容量。

核显这一档换了认法。以前是照着几条写死的路径去找，现在是在每张卡的子树里认文件名：

```text
gpu_busy_percent　→ amdgpu、nouveau 那一档，直接就是占用率
busy_percent　　　→ 每个引擎一份，取最大的那个当这一格
gt_*_freq_mhz　　 → i915 只写频率，一份占用率都不写
```

`xe` 驱动的引擎叫 `render0` / `copy0` / `compute0`，以前那条只认两三个字母的路径把它们整个漏掉了，
现在认名字不认长度。i915 那一条走的是折算：

```text
飞牛那种 Debian + i915　→ 占用 50% · i915 不写占用率，按核心频率折算（350→750 MHz）
```

折算的分子是当前核心频率，分母是 `RPn`（parked 的地板）到 `RP0`（峰值）这一档，三个数缺一个、
或者地板等于峰值，就不折算，退回只写驱动名和频率那一句。这一格是估的，句子里就带着「按核心频率
折算」这几个字，窄卡上也照样把这句带出来，不会让它冒充实测。真读到 0% 就写 0%，跟读不到是两回事。

上一版说过「接口里不写挂载点路径」，这一版推翻了那一半：登录之后看得见路径、设备名和分区名。
不出口的还是那几样——挂载点里面有什么文件、文件名、网卡名，以及 mountinfo 里那些 source / root 字段。

详见「📊 NAS 资源组件」。

## v1.0.7

改的是「某一卷到底能不能看见用量」这一件事：`deploy.sh` 探存储池不再认路径名字。

```text
以前　　→ 按 /vol1、/volume1、/storage1、/data1、/mnt/* 这几类摆法找
现在　　→ 从根目录数最多两层，凡是「跟自己的父目录不在同一块文件系统上」的目录都算一卷
```

绿联和飞牛的 `/vol1`、群晖的 `/volume1`、威联通的 `/share/CACHEDEV1_DATA`、把池子摆在 `/mnt` 或 `/media`
底下那几种，走的都是同一句判断。池子藏在二层下面的（`/vol00/<硬盘号>`、`/share/MD0_DATA`）现在也探得到，
`/vol00` 那种自己不是卷的空壳会再往里数一层。`/proc` `/sys` `/dev` `/usr` `/var` `/snap` 这类系统树整个
跳过，条目太多的目录不进去，一次最多 16 卷。`/host` 下面那一层的名字撞车时带上上一层，中文卷名也不会
把整卷挤掉——主页上看得见的名字随时能在 ✎ 里改。

卷现在多带一个文件系统类型：

```text
存储空间卡的句子末尾　→ 已用 6.0 TB · 剩 7.0 TB · 共 13 TB · btrfs
```

`btrfs` / `ext4` / `xfs` / `zfs` 这些真在用的类型一个都不滤，`nfs` / `cifs` 这类真远端也照样报容量。滤掉的是
另一头：`tmpfs` / `overlay` / `proc` / `sysfs` / `devtmpfs` / `squashfs` 这些虚拟文件系统要是坐进了 `/host`
下面，就不再当一卷列出来——那串数字不是任何人的存储池。

新加一节「为什么不靠 docker.sock 拿宿主机容量」，把两件事的边界写明白：

```text
Docker 组件 → 要 socket，只到容器状态与启停为止
逐卷用量   → 要 /host 那一行只读挂载，跟 socket 一点关系都没有
```

`docker system df` 给的是镜像、容器、卷各自占了多少，`docker info` 那几行数字是容器自己那层 overlay 的账，
两处都不是宿主机文件系统的容量，所以卷的读数从来没用过 socket。某一卷的账是在它的只读挂载点上直接问文件
系统要的，拿到的就是宿主机那一卷自己的数字——不是容器视角的那一套。主页上还是只有数字：接口里不写挂载点
路径，也没有网卡名和文件名。

详见「📊 NAS 资源组件」。

## v1.0.6

新增：硬盘那一行现在和存储空间一样，报已用 / 剩余 / 百分比，带那根用量条。

```text
以前　　→ WDC WD100EFAX-68 · 954 GB
现在　　→ WDC WD100EFAX-68 · 已用 76.9 GB · 剩 20.7 GB · 共 97.6 GB · 79%
```

多行的卡（NAS 总览、自定义读数）地方小，写的是短的那句：

```text
冷数据盘　　剩 20.7 GB / 97.6 GB
```

盘的「共」是这块盘上文件系统加起来的容量，不是 `/sys/block` 写的那个裸容量：分区表和没分出去的空格算不进「还能写多少」，文件系统满才是真满。裸容量照旧读，只在认不到文件系统时用来兜底那一行。

对不上号的时候不猜，退回只报容量并写明卡在哪一步：

```text
这台机器上没有 /proc/self/mountinfo → 容器里看不见这份挂载表
这一层里没挂进来的卷　　　　　　　　 → 容器里没挂到任何卷
挂载表里对不上这些卷的路径　　　　　 → 卷在，但认不出它落在哪块盘
没找到挂在这块盘上的文件系统　　　　 → 这一行点名的那块盘上没有可对上的卷
```

镜像、软 RAID 的文件系统是摊在几块盘上的，这份账分不到单块盘头上，所以每一块盘各记一次整组的数字，单指标卡的句尾会标一句「（整组叠出来的）」。

边界照旧：这份用量是拿挂载表第三栏的设备号对上 `/sys/block/<盘>/<分区>/dev` 归过去的，全程只比 `8:1` 这样的数字串，挂载点路径和 `/dev/*` 的名字都不出口，接口回来的还是全是数字。详见「📊 NAS 资源组件」。

## v1.0.5

新增：读数卡上的每一行也能各自改名。

「应用矩阵」那一栏每张读数卡右边的 ✎，除了名称和图标，现在还会把这张卡当前画的每一行列出来：左边那列灰字是这一行默认的名字，右边那一格填你想叫的。

```text
volume1　　　　　→ 影音池
WDC WD100EFAX-68 → 仓库盘
内存　　　　　　 → 运行内存
```

于是同一块硬盘在「NAS 总览」那张卡上叫「仓库盘」、在自定义卡里叫「冷备份那块」，各叫各的。留空的那几行照默认名，填了字的只改这一张卡上的显示，别的卡不动。

盘换了型号、卷重新探出来，小名还认得那一行；不想要了就把那一格清空。只有「内存」卡和「单个存储空间」卡没有这一列——它们只有一行，那行的名字本来就写在卡片标题上。

硬盘那一行报的还是型号加总容量：sysfs 那里只有型号和大小，盘的用量得绕一层、从它上面的文件系统归过来，所以这一版的盘只能按名字改称呼，还没有百分比那根条（后面那一版补上了）。

详见「📊 NAS 资源组件」。

## v1.0.4

修复：真机上「硬盘读不到」和「核显读不到」这两件事。

```text
硬盘　　→ /sys/block 下面每一项都是符号链接，之前按目录类型去认，一块盘都剩不下；现在只认名字，认盘改成排除名单（loop / ram / zram / sr / md / dm- 这些不算盘），各家那些对不上的盘名（sdX、nvmeXnY、mmcblkX、群晖的 sata1）都进得来
核显　　→ 以前只读 amdgpu 才写的那一个百分比；现在先看 gpu_busy_percent，再退到每个引擎的 busy_percent 取最大值（i915 只写这一份），两处都没有才算读不到
```

读数卡上的「读不到」现在都带原因，写在同一行：括号里给驱动名和当前 / 峰值频率，硬盘那一行给的是卡在哪一步（看不见 sysfs、还是排除之后没剩盘）。详见「📊 NAS 资源组件」里那几句「读不到」的对照表。

新增：读数卡的名字和图标可以改了，读数本身照旧不能改。「应用矩阵」那一栏每张读数卡右边的 ✎ 打开只有名称和图标两件事，图标留空就用这张卡自带的那枚描边图形，也能换成 Emoji 或上传图片。

## v1.0.3

新增：读数卡多了三种读数，并且可以自己挑要哪几行。

```text
CPU　　→ 占用百分比 + 核心数 + 1 分钟负载
网络　　→ 下行 / 上行速率
GPU　　 → 占用百分比（驱动没写这一项就直说读不到）
```

原来那三种是固定内容，现在多一张「自定义读数」：勾哪几行就画哪几行，内存 / CPU / 网络 / GPU / 每个卷 / 每块盘随便组合，想摆几张摆几张。

```text
NAS 总览　　　→ 内存 + 每个卷 + 每块物理盘
内存　　　　　→ 单独一张内存用量卡
单个存储空间　→ 一个卷一张卡
自定义读数　　→ 自己勾出来的行
```

卷也不再只有数据盘那一卷：`deploy.sh` 每次部署自动探这台 NAS 的存储池，探到的每一卷各写一行只读挂载，主页因此能列出全部卷和硬盘。

```text
HOST_VOLUMES 留空　　→ 自动探测（默认）
HOST_VOLUMES 写目录　→ 只挂点名的那几卷
HOST_VOLUMES=none　　→ 只挂数据目录，不探测
```

NAS 上新增或删除卷之后，重跑一次 `./deploy.sh` 就会跟着更新。边界照旧：页面只报容量数字，接口里没有挂载点路径也没有文件名；但卷挂进容器之后，容器进程技术上就能读那一卷的内容，不接受这个代价就写 `none`。

改动：主页的容器卡片不再显示运行状态后面那行镜像名小字；「应用矩阵」那一栏改成按宽度自动排的网格。

详见「📊 NAS 资源组件」。

## v1.0.2

新增：主页上多了三类 NAS 资源读数卡，在「应用矩阵」那一栏点一下就加。

```text
NAS 总览　→ 内存 + 每个卷 + 每块物理盘，一张卡看完
内存　　　 → 单独一张内存用量卡
存储空间　 → 一个卷一张卡，几个卷就能摆几张
```

每张卡 5 秒刷一轮，用量过 80% 数字和容量条转琥珀、过 90% 转红；坐标、长宽和容器组件一样，在主页上长按半秒拖到任意位置。

只报容量，不读内容：内存取 `/proc/meminfo`，物理盘只取型号和容量，卷用量走 `statfs`。接口里没有挂载点路径，也没有文件名，任何时候都不会去翻卷里的东西。

默认只看得见数据目录所在的那一卷；要逐卷显示，就给那一卷加一行只读挂载（`deploy.sh` 用 `HOST_VOLUMES` 生成），页面会自动多出对应的卡。详见「📊 NAS 资源组件」。

## v1.0.1

修复：应用程序只填内网或者外网网址时，内外网都使用这个网址访问。

旧版要一个应用把两条网址都填全，只填一条的卡片切到另一种模式就变灰、点了不跳转。

现在只填一条就够：

```text
内网工具　→ 只填内网网址
外部站点　→ 只填外网网址
```

两种模式下都走这一条，卡片照常新窗口打开。

两条网址都填的应用仍然严格分开，切换模式各走各的；分组固定的 `netMode` 也没有变。规则详见「🌐 内网 / 外网」。
